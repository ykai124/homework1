## 解題說明

本題要求實作 Ackermann（阿克曼）函數，並分別使用「遞迴」與「非遞迴」兩種方式進行計算。

### 解題策略

1. 遞迴方法
先依照 Ackermann 函數的定義建立三種判斷情況：
當 m == 0 時，直接回傳 n + 1。
當 m > 0 且 n == 0 時，計算 A(m-1, 1)。
其他情況則計算 A(m-1, A(m,n-1))。
透過函數自己呼叫自己，可以直接按照數學公式逐層計算，因此實作方式較為直觀。
2. 非遞迴方法
非遞迴方法不能讓函數自己呼叫自己，因此使用陣列建立一個 Stack，模擬遞迴過程中系統所使用的呼叫堆疊。
程式使用 while 迴圈持續處理 Stack 中的資料：
從 Stack 取出目前的 m。
根據 m 和 n 的值判斷目前符合哪一種 Ackermann 函數條件。
如果還有後續工作需要處理，就將相關的 m 值依照原本遞迴的順序放入 Stack。
當 Stack 清空時，代表所有計算都已完成，此時 n 即為最後結果。
3. 結果驗證
最後讓兩種方法使用相同的 m 和 n 進行計算，將兩者的結果進行比較。如果結果相同，則代表非遞迴方法成功模擬遞迴方法的計算過程。

## 程式實作

以下為主要程式碼：
#include <iostream>
using namespace std;
int AckermannRecursive(int m, int n)// 遞迴版本
{
    if (m == 0)
    {
        return n + 1;
    }
    else if (n == 0)
    {
        return AckermannRecursive(m - 1, 1);
    }
    else
    {
        return AckermannRecursive(m - 1, AckermannRecursive(m, n - 1));
    }
}
int AckermannNonRecursive(int m, int n)// 非遞迴版本
{
    int stack[10000];
    int top = -1;

    stack[++top] = m;

    while (top >= 0)
    {
        m = stack[top--];

        if (m == 0)
        {
            n = n + 1;
        }
        else if (n == 0)
        {
            n = 1;
            stack[++top] = m - 1;
        }
        else
        {
            stack[++top] = m - 1;
            stack[++top] = m;
            n = n - 1;
        }
    }

    return n;
}

int main()
{
    int m, n;
    cout << "請輸入 m 和 n：";
    cin >> m >> n;
    cout << "遞迴結果：" << AckermannRecursive(m, n) << endl;
    cout << "非遞迴結果：" << AckermannNonRecursive(m, n) << endl;
    return 0;
}
## 效能分析

1. **時間複雜度：**程式的時間複雜度為 $O(A(m,n))$。
2. **空間複雜度：**程式的空間複雜度為 $O(D(m,n))$（遞迴版本）與 $O(1)$（非遞迴版本）。

## 申論及開發報告

### 選擇遞迴與非遞迴兩種方法的原因

本程式同時使用遞迴與非遞迴兩種方式計算 Ackermann 函數，主要是為了比較兩種不同的實作方式。

#### 1. 遞迴版本的優點

**程式邏輯簡單直觀**

Ackermann 函數本身就是以遞迴方式定義，因此可以直接依照數學公式撰寫程式。

例如：

$$
A(m,n)=A(m-1,A(m,n-1))
$$

可以直接對應到程式：

```cpp
return AckermannRecursive(m - 1,
                          AckermannRecursive(m, n - 1));
```

這種寫法與數學定義非常接近，因此程式碼較容易理解。

**容易表達遞迴的概念**

每一次函數呼叫都會將原本的問題拆解成更小的問題，直到符合基本條件後再逐層返回結果，因此適合用來學習遞迴的運作方式。

#### 2. 非遞迴版本的優點

非遞迴版本不直接呼叫自己，而是利用陣列建立 Stack，模擬遞迴過程中系統所使用的 Call Stack。

這種方法可以讓程式自行管理尚未完成的計算工作，了解遞迴背後實際的堆疊運作方式。

例如，原本由系統自動管理的函數呼叫：

```text
Ackermann
    ↓
Ackermann
    ↓
Ackermann
```

在非遞迴版本中改由：

```text
Stack Push
    ↓
Stack Pop
    ↓
Stack Push
    ↓
Stack Pop
```

進行模擬。

#### 3. 兩種方法的比較

遞迴版本的程式碼較簡潔，而且與 Ackermann 函數的數學定義直接對應，因此容易理解與實作。

非遞迴版本雖然程式較複雜，但可以了解如何利用 Stack 將遞迴轉換成迭代方式，並避免直接使用系統的遞迴 Call Stack。

兩種方法的時間複雜度皆非常高，因為 Ackermann 函數本身具有極快的成長速度。因此實際測試時只能使用較小的 $m$ 與 $n$ 值。

透過本次實作，可以了解遞迴函數的運作方式，以及如何利用 Stack 將遞迴演算法轉換成非遞迴演算法。
